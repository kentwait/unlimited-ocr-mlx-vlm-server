## Mental Model

A React Start app has three required author-owned surfaces:

1. Build plugin: `tanstackStart()` integrates route generation, client/server builds, server function transforms, import protection, prerendering, manifests, and virtual entries.
2. Router entry: `src/router.tsx` exports `getRouter()`.
3. Routes: files under `src/routes`, with `src/routes/__root.tsx` as the document shell.

Default client and server entries exist. Create `src/client.tsx` or `src/server.ts` only when customization is needed.

## Dependencies

Core dependencies for React Start apps:

```sh
pnpm add @tanstack/react-start @tanstack/react-router react react-dom
pnpm add --save-dev typescript @types/react @types/react-dom @types/node vite @vitejs/plugin-react
```

Require Node.js LTS and pnpm. Follow the repository's pinned versions when they satisfy those requirements.

## Common Imports

- UI routing, root routes, head/script helpers, redirects, and router creation usually come from `@tanstack/react-router`.
- Server functions, Start middleware, execution-boundary helpers, `createStart`, `Hydrate`, and `useServerFn` come from `@tanstack/react-start`.
- Server request/response/cookie/session helpers come from `@tanstack/react-start/server` and must stay server-only.
- Custom client entry helpers come from `@tanstack/react-start/client` when an app defines `src/client.tsx`.
- Custom server entry helpers come from `@tanstack/react-start/server-entry` when an app defines `src/server.ts`.
- The Vite plugin comes from `@tanstack/react-start/plugin/vite`; match existing Rsbuild plugin subpaths/imports when the app uses Rsbuild.

## TypeScript Basics

Use strict TypeScript. Follow the installed Start scaffold's supported compiler
target; this framework build setting overrides **ts-coder**'s greenfield target
when they differ. The Start docs call out these important settings:

```json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "moduleResolution": "Bundler",
    "module": "ESNext",
    "target": "ES2022",
    "skipLibCheck": true,
    "strictNullChecks": true
  }
}
```

Do not enable `verbatimModuleSyntax` casually; the docs warn it can cause server bundles to leak into client bundles.

## Vite Plugin Ordering

`tanstackStart()` should run before React's Vite plugin.

```ts
import { tanstackStart } from '@tanstack/react-start/plugin/vite'
import { defineConfig } from 'vite'
import viteReact from '@vitejs/plugin-react'

export default defineConfig({
  server: { port: 3000 },
  plugins: [tanstackStart(), viteReact()],
})
```

TanStack Start examples commonly add Tailwind before Start and Nitro after React:

```ts
plugins: [tailwindcss(), tanstackStart({ srcDirectory: 'src' }), viteReact(), nitro()]
```

Match the existing app's adapter and plugin order when editing an app.

## Required Files

```text
src/
  router.tsx
  routeTree.gen.ts   # generated
  routes/
    __root.tsx
    index.tsx
  features/
    home/
      pages/
        home-page.tsx
```

Do not hand-author `routeTree.gen.ts` in normal app work. It is generated by Start/router tooling during dev/build.

Keep `src/routes` focused on file-route declarations and routing-specific
configuration. Put the first page's UI in `src/features/home` and import it
into `src/routes/index.tsx`. Add `src/shared/components` only for proven
cross-feature UI, and add `src/lib` for reusable app utilities or
infrastructure glue used by routes, features, and entries. Do not pre-create
empty directories.

See [feature-architecture.md](feature-architecture.md) before choosing where
new application code belongs.

## Router Entry

`src/router.tsx` must export `getRouter()` and return a new router instance each time:

```tsx
import { createRouter } from '@tanstack/react-router'
import { routeTree } from './routeTree.gen'

export function getRouter() {
  return createRouter({
    routeTree,
    defaultPreload: 'intent',
    scrollRestoration: true,
  })
}
```

Use router defaults for app-wide error and not-found components when the app needs shared fallbacks.

Register the router type once so generated route APIs and hooks stay typed:

```tsx
declare module '@tanstack/react-router' {
  interface Register {
    router: ReturnType<typeof getRouter>
  }
}
```

Use `createRootRouteWithContext<...>()` when the root route needs typed router context such as a `QueryClient`, current-user context, feature flags, locale, or request-derived app context.

## Root Document

`src/routes/__root.tsx` is always matched and renders the document frame. Include `<HeadContent />` in `<head>` and `<Scripts />` near the end of `<body>`.

```tsx
import { HeadContent, Outlet, Scripts, createRootRoute } from '@tanstack/react-router'
import type { ReactNode } from 'react'

export const Route = createRootRoute({
  component: RootComponent,
})

function RootComponent() {
  return (
    <RootDocument>
      <Outlet />
    </RootDocument>
  )
}

function RootDocument({ children }: Readonly<{ children: ReactNode }>) {
  return (
    <html>
      <head>
        <HeadContent />
      </head>
      <body>
        {children}
        <Scripts />
      </body>
    </html>
  )
}
```

Root routes can also define app-wide route context, `beforeLoad`, `head`, `links`, `headers`, and `scripts` when the app needs current-user loading, metadata, response headers, or CSP-aware script handling. Keep document output deterministic for SSR hydration.

For auth, a common pattern is a root `beforeLoad` that calls a current-user server function and returns `{ user }` into route context, followed by pathless protected routes for UX redirects. Private server functions and server routes must still authorize internally.

## Optional Entries

Create `src/client.tsx` for custom hydration wrappers, providers, strict mode changes, transitions, or client instrumentation.

Create `src/server.ts` for custom fetch handling, host integration, request context, or server instrumentation. Server entries export a fetch-style handler that passes requests through Start's server handler.

Create `src/start.ts` only for global Start configuration such as request middleware, function middleware, serialization adapters, `defaultSsr`, or server function fetch config. If adding `src/start.ts`, include server-function CSRF middleware unless the app deliberately enforces an equivalent protection elsewhere.

## Scaffold Checklist

- Install dependencies and configure strict TypeScript.
- Add `vite.config.ts` or `rsbuild.config.ts` with `tanstackStart()`.
- Add `src/router.tsx` with `getRouter()`.
- Add `src/routes/__root.tsx` with document shell, `<HeadContent />`, and `<Scripts />`.
- Add a first feature page under `src/features/<feature>/pages` and import it
  from `src/routes/index.tsx`, which retains the route declaration.
- Run the app/build command so `routeTree.gen.ts` is generated.

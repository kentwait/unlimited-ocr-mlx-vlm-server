## Error Boundaries

TanStack Start uses TanStack Router route-level error boundaries. Configure app defaults in `src/router.tsx` and override per route for page-specific recovery UI.

```tsx
import { ErrorComponent, createRouter } from '@tanstack/react-router'
import { routeTree } from './routeTree.gen'

export function getRouter() {
  return createRouter({
    routeTree,
    defaultErrorComponent: ({ error }) => <ErrorComponent error={error} />,
  })
}
```

Use structured results for expected form validation failures. Throw errors for unexpected failures that should be handled by route/component error UI.

Keep `errorComponent`, `notFoundComponent`, and `pendingComponent` route
options in the route module. When fallback UI is feature-specific, define the
rendered component in that feature and import it into the route option. Put an
app-wide, feature-agnostic fallback in `src/shared/components`.

## Not Found and Redirects

Configure a default not-found component in the router for app-wide fallback. Throw `notFound()` from loaders or server functions when a requested resource does not exist.

Use `redirect` from `@tanstack/react-router` in route lifecycles or server functions for auth and navigation outcomes. Route redirects improve UX; server functions and server routes still protect private data internally.

## Pending, Mutation, and Deferred UI

- Use route `pendingComponent` or router pending defaults for route-level loading.
- Use local component state for button/form mutation feedback.
- Use deferred data when a route can render meaningful UI before slower data resolves.
- Keep server-only work behind server functions even when deferred.
- Preserve layout and accessibility in loading fallbacks.
- Keep route fallback configuration in `src/routes` and feature-specific
  fallback rendering in the owning feature slice.

## Hydration Safety

Avoid non-deterministic render output during SSR/hydration:

- Do not render time, random values, browser-only APIs, media query values, `window`, or `localStorage` during initial SSR/client hydration without guards.
- Move browser-only reads into effects or client-only helpers.
- Keep first render output consistent between server and client.

## Selective SSR

Route `ssr` can be `true`, `false`, `'data-only'`, or a server-only function of route state such as params/search. Use it when a page needs client-only rendering, data-only SSR, or conditional SSR based on request-independent route state.

Child routes can only become more restrictive than parents. A root `shellComponent` still renders the document shell even when a route component is not SSR-rendered.

## Plugin Responsibilities

The Start plugin handles:

- route tree generation
- virtual client/server/router/start entries
- server function transforms and manifests
- import protection
- client and server builds
- prerendering and SPA shell output
- asset/client base paths

High-value plugin options from the schema include `srcDirectory`, `router.entry`, `router.basepath`, `client.entry`, `client.base`, `server.entry`, `serverFns.base`, `serverFns.disableCsrfMiddlewareWarning`, `pages`, `sitemap`, `prerender`, `spa`, and `importProtection`.

Additional source-backed options worth checking include `server.build.staticNodeEnv`, `server.build.inlineCss`, and `serverFns.generateFunctionId`. Treat custom function IDs, base paths, and entry points as deployment-affecting changes.

Inspect the app's actual plugin config before assuming defaults.

## Generated Files

Normal Start apps should expect:

- `src/routeTree.gen.ts`, generated by Router/Start tooling.
- virtual imports such as `#tanstack-router-entry` and `#tanstack-start-entry`.
- server function manifests used by server function lookup and transport.

Do not hand-edit generated route trees except in test/example fixtures that intentionally commit generated output.

## Import Protection

Import protection is experimental and enabled by default. It blocks
environment-specific imports such as `*.server.*` in client bundles,
`*.client.*` in server bundles, and `@tanstack/react-start/server` in client
code. Preserve this protection unless there is a deliberate, tested reason to
change it, and verify custom options against the installed Start version.

Custom import protection can define client/server file and specifier patterns,
include/exclude filters, `behavior`, `onViolation`, `log`, and `maxTraceDepth`.
Prefer fixing the import graph over weakening protection.

## Static Prerendering

```ts
tanstackStart({
  prerender: {
    enabled: true,
    crawlLinks: true,
    failOnError: true,
  },
})
```

Dynamic routes need discoverable links or explicit page entries. API-only routes and layout-only routes are not useful prerender targets.

## SPA Mode

SPA mode builds a static shell while preserving Start features when server endpoints remain reachable.

```ts
tanstackStart({
  spa: { enabled: true },
})
```

Deployment rewrites must serve assets normally, route `serverFns.base` such as `/_serverFn/*` to the server when server functions exist, route server route paths to the server when needed, and rewrite remaining app routes to the shell. Put server function and server route rewrites before static fallback or generic app-shell middleware so RPC/API requests are not swallowed by the SPA shell.

## Custom Server Entries

Custom server entries should export a fetch-style handler and route requests through the Start server handler. Keep deployment routing aligned with the app's configured `server.entry`, `client.base`, `router.basepath`, and `serverFns.base`.

## Head, Scripts, and CSP

The root document owns `<HeadContent />` and `<Scripts />`. Keep those in the document shell, and follow the app's existing router/root-document CSP pattern for nonces or script handling. Avoid custom inline scripts when CSP is strict.

## Hosting Notes

Do not assume one output path across adapters.

- Vite + Nitro examples often run `node .output/server/index.mjs`.
- Rsbuild Node docs describe client assets under `dist/client` and server bundles under `dist/server`.
- Cloudflare and Netlify have adapter-specific config.

Match the app's existing bundler and adapter.

## Validation Commands

Use configured pnpm package scripts such as:

```sh
pnpm run build
pnpm run lint
pnpm test
```

In repos that use Nx, prefer targeted project commands:

```sh
CI=1 NX_DAEMON=false pnpm nx run <project>:<target> --outputStyle=stream --skipRemoteCache
```

Run one Nx command at a time and prefer targeted package tests before broader affected runs.

## Build/Deploy Checklist

- Inspect plugin config before assuming defaults.
- Keep `tanstackStart()` before React's Vite plugin in Vite apps.
- Do not edit generated route trees except in fixtures that commit them.
- If changing `serverFns.base`, update deployment rewrites and tests.
- If adding `src/start.ts`, add CSRF middleware unless deliberately handled elsewhere.
- If enabling SPA mode, document/implement rewrites for server functions and server routes.
- If changing import protection, preserve client/server safety and add validation coverage.
